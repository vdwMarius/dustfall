# Phase 3 habitat module

Author with `Scripts/build_phase3_habitat.py` inside the dedicated foundation
editor. The builder replaces its tagged geometry and the old sealed Phase 1
habitat. It preserves terrain, landmarks, routes and character graphs. The
shell now uses project-owned curved static meshes generated by
`Scripts/habitat_pod_meshes.py`, with superellipse pressure hull panels,
construction seams/ribs, a convex rear dome, holed front cap, inset warm windows,
curved airlock barrel and peeled rear damage panels. Materials use licensed
Quixel rust albedo/roughness/normal detail; furniture retains modular primitives
and licensed scanned industrial equipment. The result is a rounded industrial
pod implementation; it does not establish reference-quality art acceptance.

2026-11-13 authoring results: the first eight custom meshes were imported with
Nanite enabled and saved, and actual imported Z-up hull bounds verified
(571.75,420,240) cm half extents. A rendered exterior inspection confirmed the
rounded silhouette, but found overly broad cardinal seams, a clean finish and
the oversized legacy foundation slab. Source revisions tighten seams, remove
only the explicitly tagged temporary slab, add curved chip/runoff/dust overlays
and repair plates (eleven meshes total), straps and moving door details. These
last revisions were rebuilt and saved at 2026-11-13 00:59 local time. The single
final exterior capture under `Saved/Codex/Phase3Art/habitat_exterior.png` was
visually inspected: rounded weathered silhouette, closed narrow seams, two warm
windows, damaged rear panels, framed airlock, solar and straps are present, and
the oversized slab is gone. The capture also shows the new terrain hill behind
home. Wear currently includes broad procedural mottling and modular patches;
fine hero-asset panel/paint detail and subjective reference acceptance remain
limitations. The playable aisle/door coordinates were retained, but no new
full traversal regression was run because the user deferred heavy testing.

## Airlock

`/Game/Habitat/BP_DustfallHabitatDirector` runs entirely in Blueprint. Near home,
press E to request the 12-second entry or exit cycle. A sign marks the control.
Walk through the first open door into the chamber, wait for pressure cycling,
then walk through the opposite door. Requests while cycling or far from home
are ignored. The callable `DF_RequestAirlock` event uses the same guarded path.

The near door opens for seconds 0–4; both doors seal for seconds 4–6; the far
door opens for seconds 6–10; both doors seal by second 12. The cycle pauses
before closing if the player occupies the active doorway, also keeping the
opposite door closed. This version uses instantaneous door movement rather than
a finished animated, sounded pressure-cycle presentation.

## Integration contract

`Saved/Codex/phase3_habitat_build.json` records world-space centimetres:

| Field | Offset from original ground-plane habitat origin |
| --- | --- |
| `HabitatCenter` | (0, 0, 235) |
| `HabitatHalfExtent` | (475, 325, 185), an extent rather than an offset |
| `CloneSpawn` | (-120, 0, 148), player capsule centre |
| Main room floor top | Z + 50 |
| Inner door plane | X + 500 |
| Outer door plane | X + 1000 |

The sanctuary box excludes the airlock. Survival owns oxygen, interior state,
refill and respawn; this builder updates the matching fields on an existing
`BP_SurvivalDirector_C` instance. If survival is authored afterward, consume the
report. On repeated habitat builds the origin comes from the director's
`HabitatOrigin`, or the `P3_Hab_Floor` actor centre minus 25 cm Z.

The old `Hab_Base_Temporary` actor is removed. `Scripts/habitat_layout.py` reads
the live Phase 3 director/floor or the original Phase 1 base. The Phase 2 landmark
and route builders use this lookup; route rebuilds preserve the Phase 3 ramp
instead of adding a second ramp. This compatibility does not make the full
legacy Phase 2 rebuild the correct Phase 3 build entrypoint. Keep PCG rocks and
dust placements clear of the entire home/airlock/ramp approach.

## Verification

`Scripts/verify_phase3_habitat_editor.py` creates its own PIE session and refuses
to alter an existing one. It checks Blueprint compilation, interior spawn,
closed-door capsule collision, outward and inward CharacterMovement traversal,
the interlock every callback and doorway-occupancy pause. When survival exists,
it also checks sanctuary recognition and that oxygen does not drain there.
Results go to `Saved/Codex/phase3_habitat_pie.json`.

The 2026-11-13 visual capture initially returned black because the hidden editor
was not rendering a realtime viewport. Enabling viewport realtime and explicitly
capturing the scene yielded real images under `Saved/Codex/Phase3Art/`.
`capture_phase3_art.py` now explicitly captures instead of relying on
CaptureEveryFrame. Its `HABITAT_ONLY` runpy global can limit review to the three
habitat shots. Temporary full-mip residency is restored afterward. This is art
review, not a streaming or performance pass. The user deferred heavy testing;
no new full airlock regression/persistence/package acceptance is asserted here.

This callable automation does not establish physical E input, reference-quality
art, subjective lighting or finished airlock audio/animation. Those require
separate editor/packaged review. Read the actual JSON before reporting a pass.
